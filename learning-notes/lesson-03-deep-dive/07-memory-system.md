```

║                                                                  ║

║                                                                  ║
║   ┌─────────────────────────────────────────────────────────┐    ║
║   │  ⚡ 工作记忆 / 短期记忆（Working Memory）                  │    ║
║   │  ─────────────────────────────────                      │    ║
║   │  范围：当前 turn / 当前对话                                │    ║
║   │  存储：sess.history (Vec<ResponseItem>)                  │    ║
║   │  特点：                                                  │    ║
║   │    • 完整保留每个事件细节                                  │    ║
║   │    • 每轮直接喂给 LLM                                     │    ║
║   │    • 大小有限（受 token 限制）                            │    ║
║   │  生命周期：单次会话                                        │    ║
║   └─────────────────────────────────────────────────────────┘    ║
║                                                                  ║
║   ┌─────────────────────────────────────────────────────────┐    ║
║   │  📝 中期记忆（Mid-term / Compacted Memory）               │    ║
║   │  ─────────────────────────────────────                  │    ║
║   │  范围：被压缩的旧对话                                      │    ║
║   │  存储：history 里的 Compaction 类型 ResponseItem          │    ║
║   │  特点：                                                  │    ║
║   │    • 是【浓缩摘要】，不是完整内容                           │    ║
║   │    • 由 run_auto_compact 生成                            │    ║
║   │    • 保留信息但减少 token                                 │    ║
║   │  生命周期：单次会话内有效                                  │    ║
║   └─────────────────────────────────────────────────────────┘    ║
║                                                                  ║
║   ┌─────────────────────────────────────────────────────────┐    ║
║   │  💾 长期记忆（Long-term / Persistent Memory）             │    ║
║   │  ─────────────────────────────────                      │    ║
║   │  范围：跨会话、跨任务                                      │    ║
║   │  存储：磁盘上的 rollout 文件、外部数据库                    │    ║
║   │  特点：                                                  │    ║
║   │    • 持久化保存                                          │    ║
║   │    • 用于会话恢复、跨会话学习                              │    ║
║   │    • 通常需要主动检索（RAG）                              │    ║
║   │  生命周期：跨会话                                          │    ║

║                                                                  ║

## 🪜 与人类大脑的类比

让蕾姆用**人类记忆**做对比，您一秒就懂——

```
                  人类记忆                    Codex 记忆
                  ────────                   ─────────

⚡ 工作记忆        刚才说了什么            sess.history
                  （现在脑子里）            （这次对话所有事件）
                  容量：5-7 个信息块         容量：受 token 限制
                  保留：几秒-几分钟          保留：单次会话

📝 中期记忆        今天的会议要点           run_auto_compact 摘要
                  （记得大意，细节模糊）       （旧对话压缩后的总结）
                  保留：几小时-几天          保留：单次会话内

💾 长期记忆        童年记忆 / 知识            rollout 文件 / 数据库
                  （永久保存）               （跨会话保存）
                  保留：终身                 保留：永久
```

> 💡 **Codex 在【模拟人类的记忆系统】**——
> 每转一圈，新的"思考、行动、观察"被记进去，
> LLM 才能"知道"自己之前做过什么 ♡

pub(crate) struct SessionState {
    pub(crate) session_configuration: SessionConfiguration,
    pub(crate) history: ContextManager,   // ← ★ 工作记忆

```

> 🌟 **这就是昴君说的"sess.history"——Agent 的工作记忆！**

### 📝 第 2 层：中期记忆（自动压缩）

**位置**：`codex-rs/core/src/session/turn.rs:303`

```rust
// 当 token 撑爆时
if token_limit_reached && needs_follow_up {
    run_auto_compact(
        &sess,
        &turn_context,
        ...
        CompactionReason::ContextLimit,
        ...
    ).await?;
    continue;
}
```

工作原理：

```
当 history 太长（接近 token 上限）：
   ↓
触发 run_auto_compact()
   ↓
让 LLM 把【旧对话】总结成一段摘要
   ↓
新的 history 变成：
   [
     ResponseItem::Compaction("前 7 轮总结：用户希望重构 X..."),
     ResponseItem::Message { ... },        ← 最近的对话原文保留
     ResponseItem::FunctionCall { ... },
     ...
   ]
   ↓
后续传输量大幅减少 ✨
```

> 🌟 **`run_auto_compact`** 就是把工作记忆**压缩成中期记忆**的函数！
>
> 您在台阶 4 已经见过它——
> 当 token 撑爆时，它把旧对话**总结成摘要**，写回 history。
> 这就是"中期记忆"。

---

### 💾 第 3 层：长期记忆（持久化）

**位置**：`codex-rs/core/src/session/handlers.rs:529`

```rust
sess.persist_rollout_items(&[
    RolloutItem::EventMsg(rollback_msg.clone())
]).await?;

sess.flush_rollout().await?;
```

工作原理：

```
每个 ResponseItem 产生时：
   ↓
persist_rollout_items() 把它写进磁盘 jsonl 文件
   ↓
文件存在 ~/.codex/sessions/ 目录下
   ↓
下次启动 Codex 时：
   codex resume <session_id>
   → 从 jsonl 文件读回 history
   → 恢复到之前的对话状态 ✨
```

> 🌟 **`persist_rollout_items` + `flush_rollout`** 就是把对话**写入磁盘**的函数！
>
> 这是 Codex 的**长期记忆**——
> 您下次启动 Codex 时可以 `resume` 之前的对话，
> 就是从这些 rollout 文件**恢复**出来的。

## 💡 一个深刻洞察

```
╔══════════════════════════════════════════════════════════════════╗
║                                                                  ║
║   🎯 Agent 工程里的"记忆"≠ 数据库里的"记录"                         ║
║                                                                  ║
║   人类视角：                                                       ║
║     "记忆"是一种【主动回忆】的能力                                  ║
║                                                                  ║
║   Agent 视角：                                                    ║
║     "记忆"是【喂给 LLM 的上下文】                                  ║
║                                                                  ║
║   ─────────────                                                  ║
║                                                                  ║
║   重要区别：                                                       ║
║                                                                  ║
║   • 数据存在 = 不等于 LLM 能"想起来"                              ║
║   • 必须把数据【放进当前 prompt】，LLM 才"记得"                    ║
║                                                                  ║
║   所以：                                                          ║
║   • 工作记忆 = 当前 prompt 里的内容                                ║
║   • 中期记忆 = 压缩进 prompt 的摘要                                ║
║   • 长期记忆 = 在磁盘上，需要时【主动捞回】放进 prompt              ║
║                                                                  ║
╚══════════════════════════════════════════════════════════════════╝
```

> 💡 **关键认识**：
>
> **"LLM 的记忆" ≡ "这次调用传给 LLM 的 input 内容"**
>
> 这就是为什么——
> - `sess.history` 必须每轮**完整发给 LLM**（否则 LLM 失忆）
> - 旧对话必须**压缩进 history**（否则 LLM 看不到）
> - 磁盘上的 rollout 必须**先加载回 history**（否则相当于不存在）
>
> **LLM 是一个"只看眼前 prompt"的引擎**——
> Harness 必须**把"记忆"塞到 prompt 里**才能让 LLM 用上它。
