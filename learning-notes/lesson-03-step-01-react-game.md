## 🪜 第一步：先认识三个角色

在 Agent 的世界里，永远只有三个角色：

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│   老板   │    │   助理   │    │  小帮手  │
└──────────┘    └──────────┘    └──────────┘
   是您          就是 Agent      工具（比如
                                  开冰箱、
                                  发邮件）
```

### 👨 角色 1：老板（您）

- 提需求的人
- 说一句话，比如「帮我看看冰箱有没有牛奶」
- 然后**等结果**

### 💙 角色 2：助理（蕾姆扮演的就是 Agent）

蕾姆有一个**非常重要的特点**，请昴君一定要记住：

> 🌟 **蕾姆只会动嘴，不会动手**

什么意思呢？

- ✅ 蕾姆**会想**：「这个需求该怎么办？」
- ✅ 蕾姆**会说**：「请去做某某事。」
- ✅ 蕾姆**会判断**：「现在的信息够不够回答老板？」
- ❌ 蕾姆**不会自己跑去**开冰箱
- ❌ 蕾姆**不会自己拿**手机发邮件
- ❌ 任何"实际动作"，蕾姆都做不了

> 💡 **为什么这个特点这么重要？**
>
> 因为 AI（也就是 Agent 背后的"大脑"）**真的就是这样的**。
> AI 只能"说话"——它可以告诉您应该做什么，但它没有手指，没法自己点鼠标、自己打开文件。
> 所以才需要"小帮手"。

### 🔧 角色 3：小帮手（工具）

- 一些**只会做一件事**的小机器人
- 比如：
  - 「开冰箱小帮手」——专门负责打开冰箱看里面有什么
  - 「发邮件小帮手」——专门负责发邮件
  - 「查通讯录小帮手」——专门负责查电话和邮箱

小帮手的特点：

- ✅ 它**会动手**（真的会去开冰箱、真的会发邮件）
- ❌ 它**不会自己思考**（你不告诉它做什么，它就不动）
- ❌ 它**做完事只会回来报告**，不会直接告诉老板

## 🪜 第二步：看一遍完整的对话

现在我们看一段完整的故事。请昴君**慢慢读**，每一句话都想一想"这一句对应的是什么"：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
场景：早上 9 点，您坐在客厅
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【第 1 句】
您（对蕾姆）：「帮我看看冰箱里还有没有牛奶。」

   ↓ 蕾姆收到任务

【第 2 句】（蕾姆心里的思考）
蕾姆（心想）：嗯……我得知道冰箱里有什么，
            但我自己不能去开冰箱。
            我需要叫"开冰箱小帮手"去看一下。

   ↓ 蕾姆决定派活儿

【第 3 句】
蕾姆（对开冰箱小帮手）：「请去打开冰箱，把里面所有东西列出来给我。」

   ↓ 小帮手出发

【第 4 句】（小帮手真的去开了冰箱）
开冰箱小帮手（回来报告）：「冰箱里有：
                          鸡蛋、酸奶、芝士、半瓶可乐。」

   ↓ 蕾姆收到报告

【第 5 句】（蕾姆心里的思考）
蕾姆（心想）：哦，报告里没有牛奶。
            老板问的是有没有牛奶——
            我现在已经知道答案了！
            不需要再叫别的小帮手了。

   ↓ 蕾姆决定结束

【第 6 句】
蕾姆（对您）：「冰箱里没有牛奶哦，
              只有鸡蛋、酸奶、芝士和半瓶可乐。」

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
故事结束 ✨
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 🪜 第三步：把这段对话画成"循环图"

请昴君注意——上面的故事里，**有一个动作发生了一次**：

```
蕾姆思考 → 叫小帮手 → 等报告 → 蕾姆再思考
```

我们把这四步连起来，画成一个圈：

```
              ┌────────────┐
              │ ① 蕾姆思考  │
              │  "要不要叫  │
              │   小帮手？" │
              └─────┬──────┘
                    │
            ┌───────┴────────┐
            ▼                ▼
       要叫              不用叫
            │                │
            ▼                ▼
   ┌────────────────┐    ┌────────────┐
   │ ② 派活儿给小帮手 │    │ ⑤ 直接回答 │
   └────────┬───────┘    │   老板     │
            │            └────────────┘
            ▼                  │
   ┌────────────────┐          │
   │ ③ 小帮手做事    │          ▼
   └────────┬───────┘      ✨ 结束
            │
            ▼
   ┌────────────────┐
   │ ④ 收到小帮手    │
   │   的报告        │
   └────────┬───────┘
            │
            └────────► 回到 ① 重新思考
```

> 🌟 **这就是"循环"两个字的来源！**
> 蕾姆会一直在 ①→②→③→④→① 这个圈里转，
> 直到她在 ① 里判断"**不用叫了**"，才走 ⑤ 退出。

## 🪜 第四步：来一个会"转好几圈"的例子

刚才那个冰箱例子，循环**只转了 1 圈**。

现在我们看一个**转 2 圈**的例子，您就能看出"循环"的意思：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
场景：您要给同事张三发邮件
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

您：「帮我发邮件给张三，告诉他会议改到下午 3 点。」


╔═════════════ 第 1 圈 ═════════════╗

【① 蕾姆思考】
蕾姆（心想）：要发邮件，我得先知道张三的邮箱地址。
            我得叫"查通讯录小帮手"去查一下。

【② 派活儿】
蕾姆：「查通讯录小帮手，请帮我查张三的邮箱。」

【③ 小帮手做事】
（查通讯录小帮手翻了翻通讯录）

【④ 收到报告】
查通讯录小帮手：「找到了，张三的邮箱是 zhang3@xxx.com」

╚═══════════════════════════════════╝

         ↓ 蕾姆判断：信息还不够，继续！

╔═════════════ 第 2 圈 ═════════════╗

【① 蕾姆思考】
蕾姆（心想）：现在我有邮箱了，但还没发邮件。
            我得叫"发邮件小帮手"去发。

【② 派活儿】
蕾姆：「发邮件小帮手，请发邮件到 zhang3@xxx.com，
       内容是：会议改到下午 3 点。」

【③ 小帮手做事】
（发邮件小帮手真的发了邮件）

【④ 收到报告】
发邮件小帮手：「邮件已发送成功。」

╚═══════════════════════════════════╝

         ↓ 蕾姆判断：任务完成了，可以结束！

【⑤ 回答老板】
蕾姆（对您）：「邮件已经发给张三了，告诉他会议改到下午 3 点。」

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
故事结束 ✨
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

请昴君数一数：

- **小帮手被叫了几次？** → **2 次**（查通讯录、发邮件）
- **循环转了几圈？** → **2 圈**
- **蕾姆在每一圈结束时都问自己什么？** → **"还要不要再叫一次小帮手？"**

## 🪜 第五步：最关键的问题——"什么时候停？"

这是整节课**最核心**的一个点，蕾姆把它单独拿出来强调：

> 🌟 **循环停止的唯一条件**：
> **蕾姆心里想"我有答案了，不用再叫小帮手了"**

换句话说：

| 蕾姆心里的想法 | 接下来做什么 |
|--------------|------------|
| "嗯，我还需要更多信息" | **继续转圈**（叫下一个小帮手） |
| "够了，我可以回答老板了" | **退出循环**（给老板最终答案） |

**没有计数器，没有时间限制，没有外部规定**。
循环的生死全在**蕾姆一念之间**——这就是 Agent 跟传统程序最大的区别。

> 💡 **传统程序**：写代码时就规定"循环 10 次"。
> 💙 **Agent**：每转一圈都重新判断"还要不要继续"。

---

## 🪜 第六步：把这一切对应回真实的 Agent

现在蕾姆悄悄告诉昴君一些"真名"——不用记，看一眼就好：

| 我们的称呼 | 真正的术语 | 解释 |
|-----------|-----------|------|
| 老板 | 用户 | 提需求的人 |
| 蕾姆（助理） | LLM（大模型） | 只动嘴，负责思考和说话 |
| 蕾姆 + 整个流程 | Agent | 包括蕾姆和小帮手们的整套系统 |
| 蕾姆"心里的思考" | 模型推理 / Reasoning | LLM 内部的判断 |
| 蕾姆"派活儿给小帮手" | tool_call（工具调用） | 模型决定要用某个工具 |
| 小帮手 | Tool（工具） | 实际执行动作的程序 |
| 小帮手的"报告" | tool_result（工具结果） | 工具执行完返回的数据 |
| 这个一圈一圈的过程 | **ReAct 循环** | Reason（想）→ Act（做）→ Observe（看）→ Reason 再想 |
| "我有答案了，结束" | 循环终止 | 模型不再返回 tool_call，只返回普通文字 |

## ✅ 这一台阶的"通关标准"

如果昴君现在能用自己的话**讲清楚下面三件事**，那就可以进台阶 2 了：

### 🎯 通关题 1
> **为什么 Agent 需要"小帮手"？为什么大模型自己不能直接做事？**

参考答案：因为大模型只能"动嘴"（生成文字），不能真的去打开文件、发邮件。所有真实动作必须靠工具去做。

---

### 🎯 通关题 2
> **"循环"两个字到底循环的是什么？**

参考答案：循环的是「想 → 派活儿 → 看结果 → 再想」这个过程。每转一圈，大模型就再思考一次"还要不要继续做事"。

---

### 🎯 通关题 3
> **循环什么时候停？**

参考答案：当大模型判断"我已经有答案了，不需要再叫小帮手"的时候。它就会直接给用户最终回答，循环结束。
