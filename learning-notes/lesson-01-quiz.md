|------------------------|------------|
| (a) No history rewrite | (1) 防止单条内容把上下文撑爆 |
| (b) Avoid frequent context changes | (2) 利用 LLM 服务的 prompt cache 降低成本 |
| (c) No unbounded items | (3) 上下文必须增量构建，不能改写 |
| (d) No items larger than 10K tokens | (4) 所有注入内容必须有硬上限 |

**【您的答案】**：

```
a — (_3_)  ✅ 正确
b — (_1_)  🔴 错误，正确答案是 (2)
c — (_2_)  🔴 错误，正确答案是 (4)

```

> 🔴 **批改结果：0.5/2** 🌱 需要重点复习
>
> ✅ **正确的连线**：
> ```
> a (No history rewrite)             — (3) 上下文必须增量构建，不能改写
> b (Avoid frequent context changes) — (2) 利用 prompt cache 降低成本
> c (No unbounded items)             — (4) 所有注入内容必须有硬上限
> d (No items larger than 10K tokens)— (1) 防止单条内容把上下文撑爆
> ```
>
> 🌟 **蕾姆的重点讲解**：
>
> **(b) "避免频繁修改上下文" → 为什么是 prompt cache？**
> LLM 服务有个秘密武器叫 **Prompt Cache**：连续两次请求的**前缀完全相同**，第二次便宜 10 倍 💰。
> 所以 Codex 的策略是 **"前面的内容不要动，只在后面追加"** → 让缓存命中率最高 → **省钱 + 提速**。
>
> **(c) vs (d) 最容易混的地方** ⚠️
> | 规则 | 范围 | 关键词 |
> |------|------|--------|
> | (c) No unbounded items | 所有条目都要有上限（**原则**） | "硬上限" |
> | (d) No items > 10K tokens | 单条具体到 10K（**具体数字**） | "撑爆" |
>
> - **c 是"原则"**：要求所有条目都必须有上限（不能"看心情塞"）→ 对应 (4) "硬上限"
> - **d 是"具体数字"**：单条不能超过 10K，否则会把整个上下文挤爆 → 对应 (1) "撑爆"
>
> 💡 **记忆口诀**：
> - 看到 "**unbounded**"（无界限）→ 想到 "**硬上限**"
> - 看到 "**10K**" 这个具体数字 → 想到 "**单条撑爆**"

│  ⑦ 解析 LLM 返回的 JSON（JSON 协议解析器）                │
│  ⑧ 沙箱检查：这条 shell 命令安全吗？✅ 安全              │
│  ⑨ 真正执行 shell：find src -name "*.ts" | wc -l         │
│  ⑩ 拿到结果："3"                                         │
│  ⑪ 把结果塞回上下文（不能改前面，只能在后面追加）          │
└────────────────────────┬─────────────────────────────────┘
                         │
                         │ 🔄 没有最终文本？继续循环！
                         │ （Harness 判定：tool_calls 不空 → 再调一次 LLM）
                         ▼
┌──────────────────────────────────────────────────────────┐
│ 🐎 Model 侧（第 2 次调用 LLM）                             │
│ ─────────────────────────────────────────────────────── │
│  ⑫ 看到工具结果 "3"                                       │
│  ⑬ 思考：信息够了，可以回答了                             │
│  ⑭ 输出纯文本：                                          │
│     "src 目录里有 3 个 .ts 文件" （没有 tool_calls）      │
└────────────────────────┬─────────────────────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────────────────────┐
│ 🪢 Harness 侧                                             │
│ ─────────────────────────────────────────────────────── │
│  ⑮ 检测到 tool_calls 为空 → 🛑 退出循环！                │
│  ⑯ 把最终文本流式渲染到 TUI                              │
└────────────────────────┬─────────────────────────────────┘
                         ▼
                   👤 用户看到答案 ✅


═══════════════════════════════════════════════════════════════
                        🔄 循环是怎么体现的？
═══════════════════════════════════════════════════════════════

  Harness ──prompt──→ Model
     ▲                  │
     │                  │ tool_call JSON
     │                  ▼
     └──result──── Harness 执行
                       │
                       │ 没有最终答案？
                       └──→ 再次调用 Model（回到顶部）

  循环结束条件（Harness 判定）：
  ✅ Model 返回纯文本（无 tool_calls） → 自然结束
  ⏰ 达到迭代上限 → 强制结束
  🛑 用户 Ctrl+C（CancellationToken）→ 立刻结束


═══════════════════════════════════════════════════════════════
                        💎 心智模型总结
═══════════════════════════════════════════════════════════════

   🐎 Model 做什么？     │  🪢 Harness 做什么？
   ─────────────────────┼─────────────────────────
   思考                 │  打包 prompt
   决策（要调什么工具）  │  解析 JSON
   生成自然语言         │  执行工具
                        │  沙箱检查
                        │  上下文管理
                        │  流式响应处理
                        │  循环控制 ⭐
                        │  错误处理

   一句话：
   Model = 大脑（决策）
   Harness = 身体（行动 + 安全 + 流程控制）
   Agent = 大脑 + 身体 + 一根串起两者的"循环线"
