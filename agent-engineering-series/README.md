# 💙 Agent 工程实战系列 · 八篇链路收官

> 蕾姆为昴君缝制的最后一卷「能力地图」♡
>
> **总目标**：以「基础层 → 进阶层 → 保障层」三大能力维度，把一个工业级 Agent 必须具备的八项工程能力串成一条闭环链路，并全部锚定到 OpenAI Codex 的真实源码（带 `file:line`）。
>
> 这是本仓库的**第三个学习维度**——前两卷分别从「源码通识」与「面试靶向」切入，本卷从「工程能力」切入，三者互补，缝合即闭环。

## 📖 每篇固定读法

八篇都遵循同一个结构（混合深度·三段式），蕾姆建议按这个节奏读：

| 节 | 内容 | 目的 |
|----|------|------|
| ① 本篇定位 | 链路位置 + 一句话核心 + 生活化比喻 | 先建立直觉 |
| ② 业界通用原理 | 先讲可迁移的通用做法 | 不被 Codex 绑架，能迁移到别的 Agent |
| ③ Codex 源码映射 | 带 `file:line`；有源码详讲，无源码标 🔴 | 落到真实实现 |
| ④ 设计取舍与局限 | Codex 为什么这么做 + 业界对比 | 区分「读过源码」与「会评源码」 |
| ⑤ 交叉引用 | 指向 learning-notes / interview-prep | 回去深挖 |
| ⑥ 实战/面试要点 | 三段式口述骨架 | 能脱稿讲出来 |
| ⑦ 动手任务 + 自测题 | 3~5 题 | 确认真懂 |
| ⑧ 小结 | 一句话带走 | 形成长期记忆 |

> 💡 **黄金法则**（与 `interview-prep` 一致）：永远先讲「业界通用原理」→ 再讲「Codex 怎么实现」→ 最后加一句「取舍/局限」。这三段式是源码型面试的标准答法。

## 🔴 一句话先看懂：Codex 的能力边界

| 能力 | Codex 教得了吗 | 说明 |
|------|:----:|------|
| ① ReAct | 🟢 | 走 Responses API 原生 reasoning，非自研文本协议 |
| ② 工具 | 🟢 | 工具闭环 + Find Skills 渐进式加载，亮点 |
| ③ Memory | 🟡 | 摘要压缩一流；**向量检索全无**，需外部补 |
| ④ Planning | 🟡 | core 内是 LLM 隐式规划；显式 DAG 编排在 `workflow-orchestrator-poc/` |
| ⑤ Multi-Agent | 🟢 | 进程内 Mailbox + 加密身份，亮点；**跨网络 A2A 无** |
| ⑥ 评估 | 🔴 | **全无**，本篇纯讲业界（τ-bench/LLM-as-judge） |
| ⑦ 安全 | 🟢 | 三层护栏 + HITL + guardian 熔断，工业级 |
| ⑧ 延迟 | 🟢 | 路由 + 前缀缓存 + 双传输流式，齐全 |

> 📌 **结论**：八项里 Codex 有 5 项是「教科书级」、2 项「半教」、1 项「完全不教」。知道边界，才知道去哪补。
