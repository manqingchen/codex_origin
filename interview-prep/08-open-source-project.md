# 08 · 自有开源 Agent 项目

> **面试考点 ⑧**：有开源 Agent 项目可附 GitHub 链接（可直接 review 代码）。
>
> ⚠️ 这一条 Codex **一行都教不了你**--Codex 是 OpenAI 的项目，你可以读、可以引用，但它**不是你的产出**。面试官要 review 的是你自己写的代码。详见 [GAPS 缺口 7](./GAPS-codex-cannot-teach.md)。

---

## 🎯 考点拆解

面试官想确认：你**亲手做过**一个能跑的 Agent 项目，有清晰的架构、能讲清设计取舍、代码可读。**代码量不重要，质量与表达重要**。

| 维度 | 面试官看什么 |
|------|---------|
| 能跑 | clone 下来能 `cargo run` / `python main.py` 跑起来 |
| 架构清晰 | README 有图、有模块说明、有数据流 |
| 设计取舍 | 为什么这么做、借鉴了哪里、放弃了什么 |
| 代码可读 | 结构整洁、有注释、有测试 |
| 你的深度 | 能讲清每一处「为什么」 |

---

## 💡 为什么读 Codex 不算数

- Codex 是 OpenAI 维护的大型项目，你读它是「学习」，不是「产出」。
- 面试官 review 你的 GitHub，看的是「**你**在约束下做了什么取舍」--这只能靠你自己造。
- 但**好消息**：你可以把读 Codex 的收获，用更少的代码复刻成一个自己的小项目--这样既证明读懂了，又有了产出。

---

## 🛠️ 推荐选题（按性价比排序，任选其一）

### 选题 A · 最小 ReAct Agent（重现 Codex 精髓）⭐⭐⭐⭐⭐

- **做什么**：一个支持 tool calling + checkpoint 回滚 + 多 provider 切换的最小 Agent loop。
- **覆盖考点**：② Agent Loop / ③ 工具编排 / ④ FC-ReAct / ⑦ 多模型（一半）。
- **规模**：Rust 或 Python，500-1500 行可成。
- **亮点**：把 Codex 的 `run_turn` loop + rollout + compact 用 1/100 的代码重现，README 写「借鉴 Codex 哪里、简化了哪里」。
- **建议**：这是最推荐的一选，因为它把读 Codex 的深度直接变成可 review 的产出。

### 选题 B · RAG 全链路 Demo ⭐⭐⭐⭐⭐

- **做什么**：文档 -> Chunk -> Embedding -> 向量库 -> Query Rewrite -> 检索 -> Rerank -> 生成。
- **覆盖考点**：⑥ RAG（全补）+ ⑧ 产出。
- **规模**：Python，配合 LlamaIndex / Qdrant，300-800 行。
- **亮点**：同时补最大缺口 RAG（见 [06](./06-rag-pipeline.md)）。一石二鸟。
- **建议**：如果你 RAG 是弱项，选这个。

### 选题 C · 跨网络 A2A 最小原型 ⭐⭐⭐⭐

- **做什么**：两个独立进程的 Agent，通过 HTTP/JSON-RPC 互发消息（仿 A2A），带 Agent Card 服务发现。
- **覆盖考点**：⑤ 多 Agent（补跨网络那半）+ ⑧ 产出。
- **规模**：Rust 或 Python，800-1500 行。
- **亮点**：补 Codex 的进程内 Mailbox 之外那半（见 [05](./05-multi-agent-communication.md)）。
- **建议**：如果你想突出分布式能力，选这个。

> 💡 **最省力组合**：选题 A（覆盖最多考点）+ 一个 RAG mini demo（补缺口）。两周内可成。

## 📐 项目结构建议

```
my-agent/
├── README.md            ← 最重要：架构图 + 数据流 + 取舍 + 如何运行
├── ARCHITECTURE.md      ← 模块说明、为什么这么分
├── src/
│   ├── loop.rs          ← 主循环（借鉴 Codex run_turn）
│   ├── tools/          ← 工具注册与分发
│   ├── context.rs      ← 上下文组装与压缩
│   ├── state.rs        ← checkpoint/rollout
│   └── provider.rs     ← 多模型抽象
├── examples/           ← 可跑的示例
└── tests/              ← 至少几个关键路径测试
```

---

## 📝 README 要点（面试官第一眼看这个）

1. **一句话定位**：这是什么、解决什么。
2. **架构图**：ASCII 或 mermaid，画出主循环 + 工具 + 状态流。
3. **快速开始**：clone -> 装依赖 -> 一行命令跑起来。
4. **设计取舍**：至少 3 条「为什么这么做 / 放弃了什么 / 借鉴了哪里」。
5. **与 Codex 的关系**（若是选题 A）：明确说「参考了 Codex 的 X，简化了 Y」。
6. **局限与 TODO**：诚实列出没做的。

> 💡 **面试官原话常见**：「你这个项目最得意的设计是什么？最遗憾的呢？」--README 里就埋好这两个答案。

---

## 🛣️ 学习顺序（建议 1-3 周）

1. 选定一个选题（推荐 A 或 B）。
2. 先写 README 草稿（驱动设计，避免边写边改）。
3. 实现最小可跑版本（MVP），不求全。
4. 补 1-2 个最能体现深度的特性（如 checkpoint、或 rerank）。
5. 加测试 + 例子。
6. 精修 README（架构图 + 取舍）。
7. 推到 GitHub，把链接写进简历。

## 💬 面试问答要点

**Q：你有什么开源项目？**
> 「我有一个 GitHub 项目 [链接]，是一个支持 tool calling + checkpoint 回滚的最小 ReAct Agent。架构上参考了 OpenAI Codex 的 `run_turn` 主循环和 rollout 持久化，但用 1/100 的代码重现，去掉了沙箱和多 Agent 这些重模块，聚焦在 loop + 状态恢复。最得意的设计是 X，最遗憾的是 Y。」

**Q：为什么不用现成框架（LangChain）？**
> 「我用框架也跑过 demo，但自己造一遍是为了理解 Codex 这类工业级 Agent 的内部机制--读源码和亲手实现是两回事。这个项目就是我把读到的设计落地成自己的代码。」

**Q：这个项目最难的部分？**
> （据实答，建议选 checkpoint/状态恢复 或 上下文压缩--这俩最能体现 Agent Loop 深度。）

## ⚠️ 差异注意点

| 维度 | Codex | 你的项目 |
|------|------|------|
| 归属 | OpenAI | 你 |
| 规模 | 工业级，近百 crate | 最小可跑 |
| 价值 | 学习素材 | 面试可 review 的产出 |
| 重点 | 全 | 聚焦 1-2 个考点深做 |

> 💡 **核心心法**：不要追求大而全。一个 800 行、README 清晰、能讲透取舍的小项目，远胜一个 8000 行但说不清设计的半成品。
